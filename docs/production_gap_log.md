# Production Gap Log

Shortcuts taken for the student/prototype version of Module 1, what production would do instead, and how to get there. Updated: 2026-10-16.

## Open gaps

| # | System | Shortcut today | Production version | Migration path |
|---|---|---|---|---|
| 1 | Ingest | GitHub issues are not ingested (dropped as a source) | Ingest breaking-change issue threads as a third source (`source_type: github_issue`) | Add a GitHub REST API fetcher (token from an environment variable, never in code), add `github_repo` and `github_issue_filter` to the settings file, add a chunk branch for issue threads |
| 2 | Chunk | `guess_source_url()` rebuilds each file's URL from its filename | Ingest writes `data/manifest.json` (filename to url and source_type); chunk reads it | Add manifest writing to `ingest`, replace `guess_source_url` with a manifest lookup |
| 3 | Chunk | `source_type` is inferred from filename text (`"guide"` or `"write"` in the name) | Taken from the manifest, never inferred | Same change as gap 2 |
| 4 | Chunk | Guide chunks have `version: None` | Settings holds the target version range, applied to guide chunks | Add `target_versions` to the settings file, read it in `chunk_file` |
| 5 | Chunk | Category keyword map is hardcoded in `chunk.py` | Per-library ordered list in the settings file | Move `CATEGORY_KEYWORDS` into settings (keep order, since the first match wins) |
| 6 | Chunk | **Resolved 2026-10-16.** Subsections were folded into their parent section | Each subsection is now its own unit with a `subsection` field | Done in the chunker rewrite |
| 7 | Chunk | `MAX_CHUNK_WORDS = 150` and `SHORT_ITEM_WORDS = 3` are hardcoded | Configurable per library | Move to settings with a default |
| 8 | All | Paths are relative to the working directory (`Path("data")`, `configs/...`) | Resolve from `Path(__file__).parent` so scripts run from any folder | Add a `PROJECT_ROOT` constant and build paths from it |

| 13 | Chunk | Code blocks longer than 150 words are split at a line break, which can cut an example in half | Split code on blank lines or function boundaries and repeat the introducing sentence on each piece | Make the splitter code-aware |

| 15 | Retrieve | Qdrant host/port and the embedding model name are constants in `retrieve.py` | Read from environment variables or settings, with these as defaults | Add env-var overrides |
| 16 | Retrieve | No Qdrant payload indexes on the fields we filter by (`version`, `category`, `section`) | Create payload indexes so filters stay fast at scale | Call `create_payload_index` for each filter field in `build_index` |
| 17 | Retrieve | Retrieval quality is checked on 7 hand-written queries that were built from the wording of their target chunks | An evaluation set built from real migration PRs, scored with precision and recall | System 7 |
| 18 | Retrieve | No relevance cutoff: semantic search always returns the nearest chunks, even for nonsense | A cutoff calibrated on labelled data | System 5 (matcher and reranker) |
| 19 | Scan | Variable tracking is a heuristic: assignments, annotated parameters and `with ... as` targets. Not tracked: `self.df` across methods, tuple unpacking, loop variables, results of user-defined functions. Unresolved method calls are kept only if the library documents the method name | Real type inference (pyright or jedi) | Replace `is_library_object` with a type-aware resolver; the record format stays the same |
| 20 | Scan | Only `.py` files are scanned, and the skipped-folder list is hardcoded | Jupyter notebooks included; skip list configurable | Extract code cells with `nbformat`; move `SKIP_DIRS` into settings |
| 21 | Match | The eligible version (`2.0.0`) is written by hand in `migration_filters` | Derive eligible versions from the user's from/to versions | Add `from_version` / `to_version` inputs and build the filter in code |
| 22 | Scan | Keyword arguments are recorded by name only; `**kwargs` expansions and positional arguments are not | Record positional arguments and constant values where the changelog names them | Extend the scan record |
| 23 | Match | "Removed function" is detected from the wording of the note (starts with Removed/Remove/Removal and names the function before from/in/of/with). Argument words such as `axis` or `index` can also strengthen a match | Parse each changelog entry into action, target and arguments once, at chunk time, and store them as chunk fields | Add a structured-change extractor to chunk.py |
| 24 | Match | Only the top 50 candidates per usage are examined and the top 5 kept. Very generic names (e.g. `DataFrame`, 111 notes) are truncated and always land in `review` | Argument- and context-aware matching, or an LLM judgement per usage | System 6 |
| 25 | Match | Reranking was evaluated and NOT adopted (2026-10-17). `cross-encoder/ms-marco-MiniLM-L-6-v2` and `BAAI/bge-reranker-base` were tried on 76 rule-generated positive cases, 53 names with no migration note, and the sample project. Neither improved ordering (MRR 0.961 to 0.954 for both), the 5% cutoff added 0 and 1 notes, and the large model took 7.8 s per usage | Re-test with labelled real migration PRs (System 7); adopt only if it finds relevant notes the rules miss without adding false alarms | A reranker step that reorders inside evidence tiers and adds `semantic_only` notes above a cutoff calibrated on known-irrelevant cases |
| 26 | Explain | Only usages with hard evidence (`documented_change`) are sent to the AI; name-only matches are `needs_review` with their notes listed (D30). A 3B model called some of them `affected` wrongly and cleared a real change (the `groupby` nuisance-columns note) | The AI judges name-only matches too, with a measured accuracy | Re-test a larger model on real PR labels (System 7); set `MODEL_JUDGES_REVIEW = True` only if it beats the baseline |
| 27 | Explain | One small local model (qwen2.5:3b, temperature 0) on an 8 GB laptop: about 3 to 5 s per call, a retry on 1 call in 6 | A larger or hosted model, with batching | Change `configs/llm.json`; the `llm_call` interface is already pluggable |
| 28 | Explain | The citation check proves a quote exists in a note, not that the note applies to the code (the 3B model cited real quotes for the wrong code) | A claim verifier that reads the code and the note together: the planned trust layer | Add an entailment (NLI) model after the explanation |
| 29 | Match | Matching is by function name, so a behaviour change that does not name the function is missed or only listed for review, e.g. `groupby(...).agg("sum")` vs the "nuisance columns" note | Behaviour-level matching (semantic retrieval plus rerank, or an LLM triage of notes per API area) | Re-test the reranker (gap 25) and larger models on real PR labels |
| 30 | Report | A suggested fix is shown only if the AI's wording is grounded, so "use concat() instead" in the note is lost when the AI rewrites it | Extract the fix clause from the cited note directly | Regex for "use X instead" and "in favor of X" |
| 31 | Report | Needs-review usages repeat the same note list (three `read_csv(path)` calls show the same 5 notes) | Group usages that share notes under one list | Group by function and note ids |
| 32 | Scan | An unconfirmed receiver (a plain list's `.append`) is still matched, then shown as unsure | Real type inference for receivers | Use a type checker (pyright or jedi) in the scanner |

## Dropped decisions

- **GitHub issues as a source** (Decision 2 originally included them). Dropped on 2026-10-16. The changelog pages do contain the breaking changes. A first check wrongly suggested the chunks covered them, but the chunker was dropping paragraphs, code examples and subsection titles in sections that also had lists. Fixed the same day in the chunker rewrite (832 chunks). Revisit if explanations lack the maintainers' reasoning (gap 1).
